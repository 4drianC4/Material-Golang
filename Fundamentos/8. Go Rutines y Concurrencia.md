# Go Rutines y Concurrencia

## **Conceptos**
Go facilita la concurrencia (ejecución de múltiples tareas al mismo tiempo) con dos construcciones principales:
- **Goroutines:** funciones que se ejecutan de forma concurrente (livianas y manejadas por el runtime de Go).
- **Channels:** permiten **comunicación segura entre goroutines** (sin necesidad de usar locks).
Con estas herramientas, Go permite escribir programas concurrentes de forma segura, legible y eficiente.
## **Datos clave**
- Se lanza una goroutine con la palabra clave `go` seguida de la llamada a una función.
- Las goroutines **se ejecutan en paralelo**, pero **no garantizan el orden**.
- Los channels permiten **enviar y recibir datos** entre goroutines.
- Los channels pueden ser **sincrónicos** (bloqueantes) o **bufferizados**.
- Se puede usar `select` para **esperar múltiples canales**.

## **Semántica / Estructura de Código**
## Lanzar una goroutine
```
go funcionConcurrente()
```
## Crear un canal
```
ch := make(chan int)         // canal sin buffer
ch := make(chan string, 10)  // canal con buffer
```
## Enviar y recibir datos
```
ch <- 5         // enviar
dato := <-ch    // recibir
```

## **Ejemplo 1: Goroutines simples**
```
package main

import (
    "fmt"
    "time"
)

func decirHola() {
    for i := 0; i < 3; i++ {
        fmt.Println("Hola")
        time.Sleep(100 * time.Millisecond)
    }
}

func decirAdios() {
    for i := 0; i < 3; i++ {
        fmt.Println("Adiós")
        time.Sleep(100 * time.Millisecond)
    }
}

func main() {
    go decirHola()
    go decirAdios()

    time.Sleep(500 * time.Millisecond)
    fmt.Println("Fin")
}
```
---

## **Ejemplo 2: Uso de channels**
```
package main

import "fmt"

func enviarDatos(ch chan string) {
    ch <- "Mensaje desde la goroutine"
}

func main() {
    canal := make(chan string)

    go enviarDatos(canal)

    mensaje := <-canal
    fmt.Println("Recibido:", mensaje)
}
```

## **Ejemplo 3: Channels bufferizados**
```
ch := make(chan int, 2)
ch <- 1
ch <- 2
fmt.Println(<-ch) // 1
fmt.Println(<-ch) // 2
```

### 🔍 **Ejemplo 4: Select con múltiples canales**
```
package main

import (
    "fmt"
    "time"
)

func main() {
    c1 := make(chan string)
    c2 := make(chan string)

    go func() {
        time.Sleep(1 * time.Second)
        c1 <- "Uno"
    }()

    go func() {
        time.Sleep(2 * time.Second)
        c2 <- "Dos"
    }()

    for i := 0; i < 2; i++ {
        select {
        case msg1 := <-c1:
            fmt.Println("Recibido:", msg1)
        case msg2 := <-c2:
            fmt.Println("Recibido:", msg2)
        }
    }
}
```

## **Ejemplo 5: sync.WaitGroup (esperar goroutines)**

Cuando no hay canales que bloquee la ejecución, `sync.WaitGroup` permite esperar a que un grupo de goroutines termine antes de continuar.

```
package main

import (
    "fmt"
    "sync"
)

func trabajo(id int, wg *sync.WaitGroup) {
    defer wg.Done() // marca la tarea como terminada
    fmt.Println("Goroutine", id, "terminada")
}

func main() {
    var wg sync.WaitGroup

    for i := 1; i <= 3; i++ {
        wg.Add(1)           // registra una goroutine pendiente
        go trabajo(i, &wg)  // se pasa por referencia
    }

    wg.Wait() // bloquea hasta que todas terminen
    fmt.Println("Todas las goroutines terminaron")
}
```
- `wg.Add(1)`: incrementa el contador de tareas pendientes (normalmente antes de lanzar la goroutine).
- `wg.Done()`: decrementa el contador (se llama con `defer` para que siempre se ejecute).
- `wg.Wait()`: bloquea la ejecución hasta que el contador llegue a 0.
> [!warning] El `WaitGroup` siempre se pasa **por referencia** (`*sync.WaitGroup`); copiarlo rompe la sincronización.

## **Concurrencia vs Asincronía (conceptos clave)**
- **Concurrencia:** el programa maneja varias tareas a la vez, aunque se ejecuten en **1 solo núcleo / 1 solo hilo** (el runtime de Go las intercala). Es la herramienta que aporta Go.
- **Asincronía:** una tarea no bloquea al resto mientras espera (I/O, red). Concurrencia y asincronía suelen combinarse: goroutines + canales cubren ambos.
- Go escala con **tantos núcleos como hilos tengamos**: el runtime reparte las goroutines entre los núcleos disponibles automáticamente.
