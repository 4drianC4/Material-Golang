# Shared kernel: respuestas, errores y paginación

> [!tip] Contexto
> El shared kernel (`internal/shared`) define el **contrato** entre el API y sus consumidores: la forma de toda respuesta, el sistema de errores tipados y la paginación. Unificarlo aquí es lo que hace coherente el resto del stack. Ver [[1. Arquitectura del proyecto]].

## Envoltorio unificado de respuestas (`internal/shared/response`)

Toda respuesta JSON tiene la misma forma:

```json
{
  "data": { ... },
  "meta": { "page": 1, "limit": 10, "total": 42 },
  "error": null
}
```

```go
package response

func OK(c *fiber.Ctx, data any) error {
	return c.JSON(Envelope{Data: data, Meta: nil, Error: nil})
}

func Created(c *fiber.Ctx, data any) error {
	return c.Status(fiber.StatusCreated).JSON(Envelope{Data: data})
}

func Error(c *fiber.Ctx, status int, code string, err error) error {
	return c.Status(status).JSON(Envelope{
		Data: nil,
		Error: &ErrBody{Code: code, Message: msg(code)},
	})
}

func ValidationError(c *fiber.Ctx, err validator.ValidationErrors) error {
	// 422 con los campos detallados → [[8. Validación con Validator v10]]
	return c.Status(fiber.StatusUnprocessableEntity).JSON(Envelope{
		Error: &ErrBody{Code: "validation_error", Message: "datos inválidos", Fields: fields(err)},
	})
}
```

> [!tip] Envelope vs. errores planos
> El cliente siempre puede hacer `if (r.error != null)` y saber si pudo parsear sin romperse. Alternativa usada en muchos equipos: **RFC 7807** (`application/problem+json`). Aquí se usa el envelope propio por simplicidad y consistencia interna.

## Errores tipados de dominio (`internal/shared/errors`)

Los services **nunca** devuelven `fmt.Errorf("no encontrado")` a secas: devuelven errores tipados que el handler traduce a HTTP.

```go
package errors

type ErrorKind int

const (
	KindNotFound ErrorKind = iota
	KindConflict
	KindForbidden
	KindUnauthorized
	KindValidation
	KindInternal
)

type AppError struct {
	Kind    ErrorKind
	Message string
	Code    string
	Wrapped error
}

func (e *AppError) Error() string { return e.Message }
func (e *AppError) Unwrap() error { return e.Wrapped }

// Constructores
func NewNotFound(resource string, id any) error {
	return &AppError{Kind: KindNotFound, Code: "not_found", Message: fmt.Sprintf("%s %v no encontrado", resource, id)}
}
func NewConflict(msg string) error { ... }
func NewForbidden(msg string) error { ... }
func NewInternal(err error) error { ... }
```

El handler **traduce** el error tipado a status HTTP:

```go
// internal/shared/response/from_error.go
func FromError(c *fiber.Ctx, err error) error {
	var appErr *errors.AppError
	if errors.As(err, &appErr) { // recorre la cadena de Unwrap
		switch appErr.Kind {
		case errors.KindNotFound:
			return Error(c, fiber.StatusNotFound, appErr.Code, appErr)
		case errors.KindConflict:
			return Error(c, fiber.StatusConflict, appErr.Code, appErr)
		case errors.KindForbidden:
			return Error(c, fiber.StatusForbidden, appErr.Code, appErr)
		default:
			return Error(c, fiber.StatusInternalServerError, "internal", appErr)
		}
	}
	return Error(c, fiber.StatusInternalServerError, "internal", err)
}
```

> [!warning] No exponer detalles internos
> Un error interno **nunca** debe filtrar el mensaje real (rutas de archivos, SQL, stack) al cliente: loguea el detalle (`zap.Error`) y responde genérico. Solo `Kind`/`Code` controlados llegan al consumidor → [[9. Logging con Zap]].

## Paginación (`internal/shared/pagination`)

Repos en todas las features responden con página + total → el meta llega al envelope.

```go
package pagination

type Params struct {
	Page  int // 1-based
	Limit int
}

func FromQuery(c *fiber.Ctx) Params {
	page, _ := strconv.Atoi(c.Query("page", "1"))
	limit, _ := strconv.Atoi(c.Query("limit", "20"))
	if page < 1 { page = 1 }
	if limit < 1 || limit > 100 { limit = 20 } // tope duro
	return Params{Page: page, Limit: limit}
}

func (p Params) Offset() int { return (p.Page - 1) * p.Limit }

func (p Params) Apply() func(*gorm.DB) *gorm.DB {
	return func(db *gorm.DB) *gorm.DB {
		return db.Offset(p.Offset()).Limit(p.Limit)
	}
}

type Meta struct {
	Page  int   `json:"page"`
	Limit int   `json:"limit"`
	Total int64 `json:"total"`
}

func NewMeta(p Params, total int64) Meta {
	return Meta{Page: p.Page, Limit: p.Limit, Total: total}
}
```

El repository lo usa así (ver [[5. Persistencia con GORM y PostgreSQL]]):

```go
err := q.Scopes(p.Apply()).Find(&users).Error
```

> [!tip] Límite por defecto y tope
> `limit` con tope duro (ej. 100) evita que un cliente pida 10.000 registros y tumbe la BD. Para listas muy grandes, paginación por cursor (`?after=<id>`) escala mejor que `page/limit`, que se degrada con `OFFSET` alto.

## Datos clave

- Envelope uniforme: `{ data, meta, error }` en toda la API.
- Errores de dominio tipados (`AppError` con `Kind`/`Code`) → traducción a status en el handler.
- `errors.As` para recorrer la cadena de errores envueltos.
- Paginación `page/limit/offset` con tope duro del `limit` y scope reutilizable.
- Nada de detalles internos en respuestas de error; `request_id` para correlación.
