# Configuración con Viper

> [!tip] Contexto
> Cada servicio tiene valores que cambian según el entorno (credenciales de BD, secretos JWT, puertos). Viper las unifica: base en `configs/config.yaml` y **sobreescritura por variables de entorno**, con soporte de `.env`.

[Viper](https://github.com/spf13/viper) es la librería de configuración estándar de facto en Go. Se usa aquí con dos fuentes combinadas:

1. **YAML** (`configs/config.yaml`) → valores por defecto legibles en el repo.
2. **Variables de entorno** (desde `.env` o el orquestador) → secretos y valores por entorno.

## El paquete `internal/shared/config`

El shared kernel expone la configuración tipada: Viper lee todo y lo volcamos a una struct con `Unmarshal`.

### `configs/config.yaml`
```yaml
app:
  name: mi-backend
  port: 8080
  env: development

database:
  host: localhost
  port: 5432
  user: postgres
  password: postgres
  name: mi_backend
  sslmode: disable
  max_open_conns: 25
  max_idle_conns: 5

redis:
  addr: localhost:6379
  password: ""
  db: 0

jwt:
  secret: cambiar-en-produccion
  expiration_hours: 24
```

### `internal/shared/config/config.go`
```go
package config

import (
	"github.com/spf13/viper"
)

type Config struct {
	App      AppConfig      `mapstructure:"app"`
	Database DatabaseConfig `mapstructure:"database"`
	Redis    RedisConfig    `mapstructure:"redis"`
	JWT      JWTConfig      `mapstructure:"jwt"`
}

type AppConfig struct {
	Name string `mapstructure:"name"`
	Port int    `mapstructure:"port"`
	Env  string `mapstructure:"env"`
}

type DatabaseConfig struct {
	Host         string `mapstructure:"host"`
	Port         int    `mapstructure:"port"`
	User         string `mapstructure:"user"`
	Password     string `mapstructure:"password"`
	Name         string `mapstructure:"name"`
	SSLMode      string `mapstructure:"sslmode"`
	MaxOpenConns int    `mapstructure:"max_open_conns"`
	MaxIdleConns int    `mapstructure:"max_idle_conns"`
}

type RedisConfig struct {
	Addr     string `mapstructure:"addr"`
	Password string `mapstructure:"password"`
	DB       int    `mapstructure:"db"`
}

type JWTConfig struct {
	Secret           string `mapstructure:"secret"`
	ExpirationHours  int    `mapstructure:"expiration_hours"`
}

func Load(path string) (*Config, error) {
	v := viper.New()
	v.SetConfigFile(path)          // configs/config.yaml
	v.SetEnvPrefix("APP")          // APP_* para variables de entorno
	v.AutomaticEnv()               // mapea env vars automáticamente
	v.SetConfigType("yaml")

	if err := v.ReadInConfig(); err != nil {
		return nil, err
	}

	var cfg Config
	if err := v.Unmarshal(&cfg); err != nil { // mapstructure
		return nil, err
	}
	return &cfg, nil
}
```

> [!tip] `mapstructure` vs `json`
> Viper usa el tag `mapstructure`, no `json`. Al añadir campos nuevos al YAML hay que declararlos también en la struct con su tag `mapstructure`.

## Sobreescritura con variables de entorno

Con `SetEnvPrefix("APP")` y `AutomaticEnv()`, la variable `APP_DATABASE_HOST` mapea a `database.host` (**guiones → guiones bajos**, no `database.host` con punto).

Para secretos que no deben vivir en el YAML del repo, usa el nombre **completo** de la clave:

```go
v.BindEnv("jwt.secret", "APP_JWT_SECRET")
```

### `.env.example`
El archivo `.env.example` documenta qué variables espera el servicio (sin valores reales):

```bash
# App
APP_ENV=development
APP_PORT=8080

# Database
APP_DATABASE_HOST=localhost
APP_DATABASE_PORT=5432
APP_DATABASE_USER=postgres
APP_DATABASE_PASSWORD=
APP_DATABASE_NAME=mi_backend

# Redis
APP_REDIS_ADDR=localhost:6379
APP_REDIS_PASSWORD=

# JWT
APP_JWT_SECRET=cambiar-en-produccion
```

Para cargar `.env` en desarrollo se usa `github.com/joho/godotenv` en `cmd/server/main.go`:

```go
if os.Getenv("APP_ENV") != "production" {
	_ = godotenv.Load()
}
cfg, err := config.Load("configs/config.yaml")
```

## Datos clave

- Viper unifica YAML + variables de entorno + `.env` en una sola struct tipada.
- `mapstructure` es el tag que conecta YAML con las structs de Go.
- Prefijo `APP_` evita colisiones con variables de otros servicios.
- Los secretos (JWT, passwords) **nunca** en el YAML versionado: van por entorno.
- El paquete `config` expone un constructor `Load` que el contenedor FX llama una sola vez → [[3. Inyección de dependencias con Uber FX]].
