# Cliente de APIs con Bruno

> [!tip] Contexto
> [Bruno](https://www.usebruno.com/) es el cliente de APIs **offline-first**: las colecciones viven como archivos Markdown/JSON en el repo (a diferencia de Postman, que guarda en la nube). Así la colección se versiona, se revisa en PR y cualquiera puede ejecutar los flujos del backend en local → [[1. Arquitectura del proyecto]].

## Estructura de la colección

Todo vive en la carpeta `bruno/` del repo:

```
bruno/
├── bruno.json              # metadatos de la colección
├── environments/
│   ├── local.bru           # entorno local (localhost:8080)
│   └── staging.bru         # entorno staging (si aplica)
└── auth/
│   ├── login.bru
│   └── me.bru
├── users/
│   ├── list.bru
│   ├── get.bru
│   └── create.bru
└── README.md               # instrucciones para el equipo
```

### `bruno.json`
```json
{
  "version": "1",
  "name": "mi-backend",
  "type": "collection",
  "ignore": ["node_modules", ".git"]
}
```

## Una request `.bru`

```text
meta {
  name: Crear usuario
  type: http
  seq: 2
}

post {
  url: {{base_url}}/api/v1/users
  body: json
  auth: none
}

headers {
  Content-Type: application/json
  X-Request-ID: {{request_id}}
}

body:json {
  {
    "name": "Ana Pérez",
    "email": "ana@ejemplo.com",
    "password": "password-muy-segura-123",
    "role": "staff"
  }
}

assert {
  res.status: eq 201
  res.body.data.id: isNumber
  res.body.error: isNull
}
```

## Variables y entornos

- `{{base_url}}` son **variables** que se resuelven según el **entorno activo**.
- Los entornos se definen en `.bru` dentro de `environments/`:

```text
vars {
  base_url: http://localhost:8080
  api_token: el-token-que-pegues-manualmente
}
```

- Variables de "script": en `script` de una request puedes escribir resultados en el entorno:

```text
script {
  // login.bru: guarda el token para las requests siguientes
  const res = res.body;
  bru.setEnvVar("api_token", res.data.token);
}
```

## Flujo típico de auth en la colección

1. **`auth/login.bru`** → `POST /api/v1/auth/login` con credenciales; en `script` hace `bru.setEnvVar("api_token", ...)`. → [[7. Autenticación con JWT y Argon2id]]
2. Las requests protegidas usan la variable:

```text
auth {
  mode: bearer
  token: {{api_token}}
}
```

3. El middleware `AuthRequired` valida el token → [[4. HTTP con Fiber v2]].

## Ejecutar desde CLI (CI / pre-commit)

Bruno incluye CLI (Node) para correr la colección sin abrir la app:

```bash
# ejecutar toda la colección contra el entorno local
bru run --env local

# solo el folder users
bru run bruno/users --env local

# con salida en JSON (útil para reportes)
bru run --env local --output report.json
```

Lo habitual: un job de CI arranca la app (`docker compose up`) y ejecuta `bru run` como **smoke test** → [[12. Docker, Makefile y migraciones]].

> [!tip] Convención de equipo
> Cada endpoint nuevo del backend **debe** venir con su `.bru` de éxito y al menos un caso de error (ej. credenciales inválidas → 401). Así la colección es documentación viva y ejecutable.

## Datos clave

- Colecciones versionadas en el repo (offline-first, sin cuenta ni nube).
- Variables `{{ }}` resueltas por entorno (`environments/*.bru`).
- Token JWT propagado vía `bru.setEnvVar` entre requests del flujo.
- Assertions (`assert`) para validar status y shape de la respuesta.
- CLI `bru run` para smoke tests en CI.
- Cada feature nueva = sus `.bru` de éxito + error.
