# HTTP con Fiber v2

> [!tip] Contexto
> [Fiber v2](https://docs.gofiber.io/) es el framework HTTP: router veloz (basado en **fasthttp**), API parecida a Express y middleware integrado. Aquí se usa para exponer los endpoints de cada módulo con grupos por versión y middleware global.

## La instancia de la app (`cmd/server`)

```go
package main

import (
	"github.com/gofiber/fiber/v2"
	"github.com/gofiber/fiber/v2/middleware/cors"
	"github.com/gofiber/fiber/v2/middleware/recover"
	"github.com/gofiber/fiber/v2/middleware/requestid"

	"mi-backend/internal/shared/config"
)

func NewFiberApp(cfg *config.Config, logger *zap.Logger) *fiber.App {
	app := fiber.New(fiber.Config{
		AppName:               cfg.App.Name,
		EnablePrintRoutes:     cfg.App.Env == "development",
		ErrorHandler:          customErrorHandler, // errores unificados → [[10. Shared kernel: respuestas, errores y paginación]]
		DisableStartupMessage: cfg.App.Env == "production",
	})

	// Middleware global: orden importa (se ejecutan en el orden registrado)
	app.Use(recover.New())            // evita que un panic tumbe el server
	app.Use(requestid.New())          // header X-Request-ID para trazabilidad
	app.Use(loggerMiddleware())       // log de cada request → [[9. Logging con Zap]]
	app.Use(cors.New(cors.Config{
		AllowOrigins: "http://localhost:3000",
		AllowHeaders: "Origin, Content-Type, Accept, Authorization",
		AllowMethods: "GET, POST, PUT, PATCH, DELETE, OPTIONS",
	}))

	return app
}
```

> [!warning] Fiber v2 vs v3
> Este stack usa **Fiber v2** (estable, API consolidada). Fiber v3 cambió detalles de middleware y de `fiber.New`. Verifica siempre la versión en `go.mod` antes de copiar ejemplos de internet.

## Rutas por módulo: grupos y versionado

Cada feature registra sus rutas sobre un grupo de versión:

```go
// internal/modules/user/router.go
func RegisterRoutes(h *Handler, app *fiber.App) {
	api := app.Group("/api/v1")
	users := api.Group("/users")

	users.Get("/", h.List)          // GET  /api/v1/users?page=1&limit=10
	users.Get("/:id", h.GetByID)    // GET  /api/v1/users/:id
	users.Post("/", h.Create)       // POST /api/v1/users
	users.Put("/:id", h.Update)     // PUT  /api/v1/users/:id
	users.Delete("/:id", h.Delete)  // DELETE /api/v1/users/:id
}
```

Rutas protegidas se agrupan aparte y se les aplica el middleware de auth:

```go
protected := api.Group("/products", middleware.AuthRequired())
protected.Post("/", h.Create)
```

## El handler: de la request a la respuesta

El flujo estándar de un handler:

```go
func (h *Handler) Create(c *fiber.Ctx) error {
	var req CreateUserRequest

	// 1. Parsear el body (JSON) y validar
	if err := c.BodyParser(&req); err != nil {
		return response.Error(c, fiber.StatusBadRequest, "request_invalida", err)
	}
	if err := validate.Struct(req); err != nil { // → [[8. Validación con Validator v10]]
		return response.ValidationError(c, err)
	}

	// 2. Llamar al service (lógica de negocio)
	user, err := h.svc.Create(c.Context(), req)
	if err != nil {
		return response.FromError(c, err) // errores tipados → [[10. Shared kernel: respuestas, errores y paginación]]
	}

	// 3. Responder con el contrato unificado
	return response.Created(c, user)
}
```

### Contexto útil de Fiber
- `c.Params("id")` → parámetro de ruta (`/:id`).
- `c.Query("page")` → query param (`?page=1`).
- `c.BodyParser(&req)` → decodifica JSON del body.
- `c.Get("Authorization")` → lee headers.
- `c.Locals("userID", id)` → guarda datos en el contexto (lo usa auth → [[7. Autenticación con JWT y Argon2id]]).
- `c.Context()` → `context.Context` para pasar a repos/Redis.

## Middleware propio: ejemplo de logging con Zap

```go
func loggerMiddleware(log *zap.Logger) fiber.Handler {
	return func(c *fiber.Ctx) error {
		start := time.Now()
		err := c.Next()
		log.Info("request",
			zap.String("method", c.Method()),
			zap.String("path", c.Path()),
			zap.Int("status", c.Response().StatusCode()),
			zap.Duration("latency", time.Since(start)),
			zap.String("request_id", c.GetRespHeader("X-Request-ID")),
		)
		return err
	}
}
```

> [!tip] Los middleware reciben sus dependencias
> Con FX, el middleware se registra como función que *recibe* el logger: `app.Use(loggerMiddleware(log))`, y FX se encarga de pasarlo → [[3. Inyección de dependencias con Uber FX]].

## Datos clave

- Fiber v2 usa **fasthttp** (sin dependencia de `net/http`): rápido y ligero.
- `app.Group` + versión (`/api/v1`) es la forma de organizar rutas por feature.
- El `ErrorHandler` global centraliza los errores; los handlers casi no manejan `if err` a mano → [[10. Shared kernel: respuestas, errores y paginación]].
- Los handlers son delgados: parsean, validan, llaman al service y responden.
- `c.Locals` transporta datos entre middleware y handler (id de usuario autenticado).
- Fiber soporta `fiber.NewError(status, message)` para errores "HTTP puros" dentro del flujo.
