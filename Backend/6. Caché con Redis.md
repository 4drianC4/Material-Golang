# Caché con Redis

> [!tip] Contexto
> [Redis](https://redis.io/) da caché en memoria, sesiones y rate limiting. Se usa con el cliente oficial `github.com/redis/go-redis/v9` y el patrón **cache-aside**: primero consultamos la caché; si no hay, vamos a la BD y poblamos la caché.

## Cliente (`internal/shared/redis`)

```go
package redis

import (
	"context"
	"time"

	"github.com/redis/go-redis/v9"

	"mi-backend/internal/shared/config"
)

func New(cfg *config.RedisConfig) (*redis.Client, error) {
	client := redis.NewClient(&redis.Options{
		Addr:     cfg.Addr,
		Password: cfg.Password,
		DB:       cfg.DB,
	})

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	if err := client.Ping(ctx).Err(); err != nil {
		return nil, err // la app no arranca sin Redis
	}
	return client, nil
}
```

> [!tip] Ping al arrancar
> Fallar temprano es mejor que fallar en la primera request. Con FX, si `New` devuelve error, la app no arranca → [[3. Inyección de dependencias con Uber FX]].

## Operaciones básicas

```go
// Set con expiración
client.Set(ctx, "key", value, 5*time.Minute)

// Set de un struct (JSON)
client.Set(ctx, "user:42", jsonBytes, 10*time.Minute)

// Get: recordar que devuelve error si la key no existe (redis.Nil)
val, err := client.Get(ctx, "user:42").Result()
if errors.Is(err, redis.Nil) {
	// cache miss
}

// Delete
client.Del(ctx, "user:42")

// TTL restante
ttl, _ := client.TTL(ctx, "user:42").Result()

// Hash (útil para sesiones parciales)
client.HSet(ctx, "session:abc", "userID", "42", "role", "admin")
```

> [!warning] No confundir con valor vacío
> `redis.Nil` significa *la key no existe* (cache miss). Un valor `""` o `"0"` **sí existe**: es la distinción entre "nunca cacheado" y "cacheado con valor vacío", importante en caché negativa.

## Patrón cache-aside

El caso típico: detail de un producto consultado a menudo.

```go
func (r *Repository) GetByID(ctx context.Context, tenantID, id uint) (*Product, error) {
	cacheKey := fmt.Sprintf("product:%d:%d", tenantID, id)

	// 1. Intento de caché
	raw, err := r.cache.Get(ctx, cacheKey).Bytes()
	switch {
	case err == nil: // cache hit → deserializar y devolver
		var p Product
		if json.Unmarshal(raw, &p) == nil {
			return &p, nil
		}
	case !errors.Is(err, redis.Nil): // error real de Redis → no bloquear el negocio
		r.log.Warn("redis get", zap.Error(err))
	}

	// 2. Cache miss → BD
	p, err := r.loadFromDB(ctx, tenantID, id)
	if err != nil {
		return nil, err
	}

	// 3. Poblar caché (best effort: un error de Redis no debe fallar la request)
	raw, _ = json.Marshal(p)
	r.cache.Set(ctx, cacheKey, raw, r.ttl)

	return p, nil
}
```

Puntos clave del patrón:

- La **key** incluye tenant e id → un inquilino nunca ve datos de otro.
- **TTL** siempre (invariante: la caché es un espejo, no la fuente de verdad).
- Un fallo de Redis **no** derriba la request: se degrada a BD y se loguea.
- Después de un `Update`/`Delete` se **invalida** la key (`r.cache.Del(...)`) en vez de re-escribirla, para no correr carreras con lecturas concurrentes.

## Otros usos

| Uso | API típica | Nota |
| --- | --- | --- |
| Rate limiting | `INCR` + `EXPIRE` | contador por IP/tenant con ventana fija |
| Sesiones | `HSet` / `HGetAll` | alternativa a JWT opacas (no es el caso aquí) |
| Colas simples | `LPUSH` / `BRPOP` | sustitutivo ligero de Redis Streams |
| Bloqueo distribuido | `SET key val NX PX ms` | para jobs únicos entre réplicas |

Ejemplo minimo de rate limiting por ventana:

```go
func rateLimit(ctx context.Context, client *redis.Client, key string, max int, window time.Duration) (bool, error) {
	count, err := client.Incr(ctx, key).Result()
	if err != nil {
		return false, err
	}
	if count == 1 {
		client.Expire(ctx, key, window)
	}
	return count <= int64(max), nil
}
```

## Datos clave

- Cliente oficial `go-redis/v9`; conexión validada con `Ping` al arrancar.
- Cache-aside: caché → BD → poblar caché; Redis nunca es la fuente de verdad.
- Distinguir `redis.Nil` (miss) de valor vacío; los errores de Redis degrades, no fallan la request.
- Keys con namespace por tenant y entidad (`tenant:entidad:id`), siempre con TTL.
- Invalidar (DELETE) tras escrituras; `INCR`+`EXPIRE` para rate limiting.
