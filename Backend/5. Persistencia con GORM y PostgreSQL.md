# Persistencia con GORM y PostgreSQL

> [!tip] Contexto
> [GORM](https://gorm.io/) es el ORM más usado en Go: mapea structs a tablas, genera migraciones y abstrae el SQL. Se conecta a **PostgreSQL** a través de `gorm.io/driver/postgres`.

## Conexión (`internal/shared/database`)

```go
package database

import (
	"gorm.io/driver/postgres"
	"gorm.io/gorm"
	"gorm.io/gorm/logger"

	"mi-backend/internal/shared/config"
)

func New(cfg *config.DatabaseConfig, log *zap.Logger) (*gorm.DB, error) {
	dsn := fmt.Sprintf(
		"host=%s port=%d user=%s password=%s dbname=%s sslmode=%s",
		cfg.Host, cfg.Port, cfg.User, cfg.Password, cfg.Name, cfg.SSLMode,
	)

	db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
		Logger: logger.Default.LogMode(logger.Warn), // en dev: logger.Info
	})
	if err != nil {
		return nil, err
	}

	sqlDB, err := db.DB() // acceso al *sql.DB subyacente
	if err != nil {
		return nil, err
	}
	sqlDB.SetMaxOpenConns(cfg.MaxOpenConns)
	sqlDB.SetMaxIdleConns(cfg.MaxIdleConns)
	sqlDB.SetConnMaxLifetime(time.Hour)

	return db, nil
}
```

> [!tip] DSN
> En producción se usa a menudo la URL completa: `postgres://user:pass@host:5432/db?sslmode=require`. GORM acepta ambas formas.

## Modelos (`internal/modules/<feature>/model.go`)

```go
type User struct {
	ID           uint      `gorm:"primaryKey;autoIncrement"`
	Name         string    `gorm:"size:120;not null"`
	Email        string    `gorm:"size:255;not null;uniqueIndex"`
	PasswordHash string    `gorm:"size:255;not null"`
	TenantID     uint      `gorm:"not null;index"`
	CreatedAt    time.Time `gorm:"autoCreateTime"`
	UpdatedAt    time.Time `gorm:"autoUpdateTime"`
}
```

- `primaryKey`, `not null`, `size:255`, `uniqueIndex` → definen el esquema.
- `autoCreateTime` / `autoUpdateTime` → GORM gestiona `created_at`/`updated_at` solo.
- En este proyecto multi-tenant, **casi toda tabla lleva `TenantID`** con índice → cada query debe filtrar por tenant.

> [!important] Multi-tenant
> Es fácil olvidar el filtro por tenant. Patrón seguro: el repository **siempre** recibe el `TenantID` desde el contexto (lo pone el middleware de auth → [[7. Autenticación con JWT y Argon2id]]) y lo incluye en todo `Where`.

## Repositorio (`internal/modules/<feature>/repository.go`)

El repository aísla GORM del service: el service trabaja con entidades y errores de dominio.

```go
func (r *Repository) Create(ctx context.Context, u *User) error {
	return r.db.WithContext(ctx).Create(u).Error
}

func (r *Repository) GetByID(ctx context.Context, tenantID, id uint) (*User, error) {
	var u User
	err := r.db.WithContext(ctx).
		Where("tenant_id = ? AND id = ?", tenantID, id).
		First(&u).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return nil, errors.NewNotFound("user", id) // error tipado → [[10. Shared kernel: respuestas, errores y paginación]]
	}
	return &u, nil
}

func (r *Repository) List(ctx context.Context, tenantID uint, p pagination.Params) ([]User, int64, error) {
	var users []User
	var total int64

	q := r.db.WithContext(ctx).Where("tenant_id = ?", tenantID)
	q.Model(&User{}).Count(&total)
	err := q.Scopes(p.Apply()).Find(&users).Error // scope de paginación → [[10. Shared kernel: respuestas, errores y paginación]]
	return users, total, err
}

func (r *Repository) Update(ctx context.Context, u *User) error {
	return r.db.WithContext(ctx).Model(u).Updates(u).Error
}

func (r *Repository) Delete(ctx context.Context, tenantID, id uint) error {
	return r.db.WithContext(ctx).
		Where("tenant_id = ? AND id = ?", tenantID, id).
		Delete(&User{}).Error
}
```

> [!tip] `WithContext`
> **Siempre** pasa el contexto de la request: si el cliente cancela, la query cancela. Nunca uses el `*gorm.DB` global sin contexto en handlers.

## Transacciones (`internal/shared/transaction`)

Cuando un service toca varias tablas (ej. una venta + stock), la operación debe ser **atómica**:

```go
func (s *Service) RegisterSale(ctx context.Context, req SaleRequest) error {
	return s.tx.Within(ctx, func(txCtx context.Context) error {
		// dentro de la transacción: todas las operaciones usan txCtx
		sale, err := s.saleRepo.Create(txCtx, req)
		if err != nil {
			return err // ← revierte TODO
		}
		if err := s.productRepo.DecreaseStock(txCtx, req.ProductID, req.Qty); err != nil {
			return err
		}
		return nil
	})
}
```

El gestor `transaction` envuelve `db.Transaction(func(tx *gorm.DB) error { ... })` y propaga el contexto:

```go
func (t *Manager) Within(ctx context.Context, fn func(ctx context.Context) error) error {
	return t.db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
		txCtx := context.WithValue(ctx, txKey{}, tx)
		return fn(txCtx)
	})
}
```
> Si `fn` devuelve error, GORM hace **rollback** automático; si devuelve `nil`, **commit**.

## Migraciones (`cmd/migrate`)

En lugar de una herramienta externa (golang-migrate, goose), GORM **sincroniza el esquema** desde los modelos:

```go
// cmd/migrate/main.go
func main() {
	cfg := loadConfig()
	db := database.New(cfg)

	err := db.AutoMigrate(
		&user.User{},
		&product.Product{},
		&tenant.Tenant{},
		&sales.Sale{},
	)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("migraciones aplicadas")
}
```

> [!warning] `AutoMigrate` en producción
> `AutoMigrate` solo **agrega** columnas/tablas; no borra ni altera tipos destructivamente. Para cambios destructivos (renombrar, borrar columnas) usa migraciones SQL manuales o añade columnas nuevas y migra los datos. El comando se ejecuta aparte (`make migrate`), nunca dentro de `cmd/server` → [[12. Docker, Makefile y migraciones]].

## Datos clave

- GORM mapea struct ↔ tabla con tags `gorm:"..."`.
- El repository es la única capa que habla con GORM.
- Multi-tenant → filtrar por `tenant_id` en **todas** las queries.
- `WithContext(ctx)` siempre; transacciones para operaciones multi-tabla.
- `AutoMigrate` para evolucionar el esquema; comandos migratorios en `cmd/migrate`.
- `gorm.ErrRecordNotFound` se traduce a errores tipados de dominio → [[10. Shared kernel: respuestas, errores y paginación]].
